# Optional ML component: evidence report

Generated by `python evaluate.py --ml --report`. It answers one question: **does a trained model improve on the existing rules and threat-database lookups enough to ship, measured on data it never saw?**

## Verdict

**Not adopted.** The model failed these gates: `holdout_guard`. The artifact is written with `adopted: false` and the scanner ignores it, so detection is unchanged.

**Why.** On the author's holdout the hybrid flagged 36 of 158 legitimate URLs, against 7 for the rules alone, almost all of them ordinary subdomain hosts of major sites (it also found more phishing there: recall 55% to 78%, but a false-alarm rate that high would teach users to ignore the scanner). The large recall gain on the feed test set (+81.5 points) is **not trusted**: the two classes in the feed data differ structurally (see the section below), and the model learned that difference as much as it learned anything about phishing.

**What would change the answer:** a benign sample with realistic subdomains and deep links (a vetted allow-list, or links your own users click, collected with consent), not a list of registered domains. Rebuild the data, re-run `python evaluate.py --ml --report`, and the same gates decide again. Until then the rules and threat-database lookups are the detection, and the model is not part of it.

This is a measured statement about one dataset, not a claim that the scanner 'uses AI to detect phishing'. Read the limitations before quoting any number.

## What was compared

| System | Definition |
|---|---|
| Rules | the existing URL-structure heuristics (`analyze_structure`), no threat databases |
| Model | logistic regression on host-only features, scored in plain Python |
| Hybrid | the shipped design: Suspicious if the rules *or* the model flags it |

Threat-database lookups (Safe Browsing, URLhaus) need network and API keys and are not part of any figure here. They remain the only source of *confirmed* verdicts, and the model cannot override them. Comparing the model with them directly is not possible offline; the model is judged on what it adds beyond the rules.

## Results on the independent test set

`feed_test.csv`: 254 phishing rows (OpenPhish public feed) and 1500 benign rows (top-sites list, three popularity bands). 1735 groups, none shared with training. Both classes are reduced to the same host-only form first.

| System | Recall (phishing flagged) | False-positive rate | Precision | F1 |
|---|---|---|---|---|
| Rules | 1.2% (0%–3%) | 0.1% (0.0%–0.4%) | 75.0% (30%–95%) | 2.3% |
| Model alone | 82.3% (77%–86%) | 0.9% (0.6%–1.6%) | 93.7% (90%–96%) | 87.6% |
| **Hybrid** | 82.7% (78%–87%) | 0.9% (0.6%–1.6%) | 93.8% (90%–96%) | 87.9% |

Paired bootstrap, 2000 resamples, hybrid minus rules: recall **+81.5 points** (95% interval +76.8 to +86.6); false-positive rate **+0.87 points** (95% interval +0.47 to +1.40). Model AUC on this set: 0.943. Precision here reflects 14% phishing; see the prevalence table for real traffic.

### False-positive rate by how popular the benign site is

Benign rows are drawn equally from rank bands a (1-50k), b (50k-300k) and c (300k-1M). Popular sites look tidy; a model that only learnt 'popular = benign' would look fine on band a and fail on band c. The long tail also contains junk that is not truly benign, so band c *overstates* the false-positive rate.

| Band | Benign rows | Rules flagged | Model flagged | Hybrid flagged |
|---|---|---|---|---|
| a | 500 | 0.20% | 0.60% | 0.60% |
| b | 500 | 0.00% | 0.80% | 0.80% |
| c | 500 | 0.00% | 1.40% | 1.40% |

### What precision would look like on real traffic

Using the hybrid's recall and false-positive rate from this test set. The last column uses the upper end of the false-positive interval.

| Share of scanned links that are phishing | Precision (measured FPR) | Precision (FPR at upper bound) |
|---|---|---|
| 50% | 98.9% | 98.1% |
| 10% | 90.8% | 85.5% |
| 1% | 47.2% | 34.9% |
| 0.1% | 8.1% | 5.0% |

At realistic prevalence most *Suspicious* flags from any address-shape model will be false alarms. That is why the model can only raise a caution, never a confirmed verdict.

## Gates (fixed in code before the final run)

| `recall_gain` | hybrid recall exceeds rules-only recall by >= 5 points, paired-bootstrap 95% interval above 0 | PASS |
| `fpr_ceiling` | hybrid false-positive rate on the test set: 95% Wilson upper bound <= 3.0% | PASS |
| `holdout_guard` | on the author's independent holdout, the hybrid adds at most 1 false positive over the rules | **FAIL** |
| `no_leakage_signs` | grouped-CV AUC within 0.03 of random-CV AUC, and AUC with shuffled labels within 0.45-0.55 | PASS |

## A structural difference between the two classes

| Hosts with a subdomain (www ignored) | Phishing | Benign |
|---|---|---|
| Training file | 54% | 1% |
| Test file | 79% | 1% |

**This gap is a property of how the data was collected, not of phishing.** Feed phishing is full of throw-away tenant hosts (`name.platform.tld`), while a top-sites list names registered domains. A model can score well on this test set simply by learning "has a subdomain", and would then flag ordinary sites such as `docs.google.com` or `login.microsoftonline.com`. The test-set figures above therefore **overstate** what the model would do on real traffic, and the holdout guard below exists to catch exactly this.

**Order of events, for the record.** (1) The test file was scored once, for AUC only, on three exploratory model variants, before the benign sample was widened to three popularity bands and before the selection procedure, threshold rule and gates were fixed in code; no feature, threshold or gate was set from test results. (2) The first full run failed the holdout guard. Diagnosis: all of the extra false positives were ordinary subdomain hosts of major sites. (3) A builder bug was found (benign tenants of a shared-hosting platform were collapsed into one row by keying on the registered domain) and fixed; it made almost no difference, because the top-sites list simply has almost no subdomain hosts. Features, grid, threshold rule and gates were left unchanged. The holdout guard was therefore consulted twice, and the test set is not perfectly untouched. Rebuild the data from a fresh snapshot (`python tools/build_ml_dataset.py`) and re-run `python evaluate.py --ml` before relying on these figures.

## Limitations

- **The labels are what the feeds say.** Feed entries can be stale, wrongly listed, or already taken down. The benign list is a popularity ranking, not a verified-clean list.
- **Host-only.** To keep the comparison fair the model and the rules both see only the host here. In real use the rules also see the path and query, so the rules' recall on full URLs is higher than the host-only figure (context line above).
- **Benign rows are home pages.** Real users click deep links on ordinary sites. The false-positive rate here is for host shapes, not for every page of every site.
- **Look-alike shortcuts remain possible.** Feeds are dominated by throw-away hosts on free platforms and cheap TLDs; a model can learn those habits rather than anything fundamental. It will age as attackers change habits, so re-run this evaluation on a fresh feed snapshot before each release and on a schedule.
- **It cannot see what the address does not show.** A compromised legitimate site, a trusted-platform page or an open redirect looks normal from the host. Only a threat database, or fetching the page, can catch those.
- **The score is not a probability.** It is a ranking, and no calibration is claimed; the scanner's `confidence` stays null.
