# Detection evaluation report

This report is generated by `python evaluate.py --report`. It measures how well the **URL-structure heuristics** separate phishing links from legitimate ones, on the labelled dataset in this repository. It does not measure the threat-database lookups (Google Safe Browsing, URLhaus), which need network access and API keys and are the only source of *confirmed* verdicts.

## Read this first

- **What was measured:** the URL-structure heuristics only, never the threat-database lookups.
- **The phishing URLs are synthetic.** They follow well-documented phishing patterns on invented domains. They are not a sample of real attacks, so recall here says how well the rules catch the patterns they were designed for, not how many real phishing links they would catch.
- **The legitimate URLs are real domains** written by hand. Paths were not checked to be live.
- **Dev vs holdout.** Rules were tuned by looking at every `dev` error. The `holdout` split was written after the rules were frozen and has not been used to change any rule, so it is the fairer estimate. Dev numbers are optimistic by construction. The holdout is independent of the tuning but **not of its author**: whoever wrote the rules also wrote it. A feed-based set (`tools/build_feed_dataset.py`) is the check that removes that limit.
- **Small samples.** Intervals in brackets are 95% Wilson intervals. They are wide; differences of a few points between runs or splits are not meaningful.
- **Prevalence.** 48% of the scored URLs here are phishing. Real traffic is nowhere near that, and precision depends on it. Use the false-positive rate, and the prevalence table below, to judge real-world behaviour.

## Method

1. Each URL goes through the same `classify_url()` pipeline the web app uses, with no threat-database results.
2. A URL is *predicted positive* if the verdict is Suspicious or Malicious.
3. Counts come from comparing that to the label. Precision = TP/(TP+FP), recall = TP/(TP+FN), F1 = harmonic mean of the two, false-positive rate = FP/(FP+TN).
4. Categories whose label depends on a destination the scanner never visits are listed but **not scored**: `shortener`.
5. Labels are validated on load. Unknown labels, empty URLs and duplicates stop the run.

## Limitations

- A link on a legitimate site that has been compromised, an open redirect on a trusted domain, and a malicious page on a trusted platform all look normal from the address alone. Only a threat database, or fetching the page, can catch them.
- Brand and official-domain lists are hand-maintained. A brand missing from the list is not protected, and a legitimate first-party domain missing from it can be flagged.
- The dataset is small and was written by the same people who wrote the rules, so it shares their blind spots.
- For a real benchmark, run this script on a PhishTank/OpenPhish export plus a Tranco top-sites sample (see Reproduce below) and report that instead of, or beside, these figures.

## Reproduce

```
python -m pip install -r requirements.txt
python evaluate.py --report
```

Same dataset hash and same rules hash give the same numbers. Different `tldextract` versions can differ slightly because the public-suffix list changes. To evaluate real feeds, export them to a CSV with `url,label` columns (and optionally `category`, `split`, `source`) and run `python evaluate.py yourfile.csv`.
